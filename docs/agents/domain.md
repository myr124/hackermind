# Domain docs

Use the single-context layout:
- CONTEXT.md: domain glossary.
- docs/adr/: architectural decisions, created when needed.

Before exploring the codebase, read CONTEXT.md and relevant ADRs.
Proceed silently when an optional document or directory is absent.

Use glossary terms in tickets, code, tests, and explanations.
Surface conflicts with existing ADRs explicitly.
Record resolved terminology through domain-modeling; keep
implementation details out of the glossary.
