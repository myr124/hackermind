# Progressive graph exploration

Design the initial graph experience for a 10,000-project catalog on desktop and midrange phones, without requiring every project to be drawn simultaneously. Exploration progressively reveals named problem spaces, subcategories, and projects near the area being explored; relationships influence placement rather than fixed domain compartments or inferred exclusive clusters.

A project retains one identity and may belong to multiple problem spaces. Cross-space relationships must remain discoverable when endpoints are collapsed. This supersedes the domain-hub graph direction in the earlier phase-1 spec; exact aggregation behavior, rendering technology, visibility budgets, and performance acceptance criteria remain undecided. The trade-off is giving up an all-projects-at-once view in favor of legibility and bounded rendering work.
